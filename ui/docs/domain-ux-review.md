# Domain UI/UX Review

## Scope

This review covers the admin shell context and the seven Fitz domain surfaces: KV, Queue, Stream, Lease, Notice, RPC, and Schedule. The implementation changes are UI-local and use existing generated endpoints.

## Shared Standard

- Overview pages answer domain posture with a `DomainHeader`, status badge, refresh action, snapshot metrics, loading/error/empty states, and drill-down tables.
- Realm and area pages answer which scopes exist and preserve realm, area, resource, and route-family separation.
- Resource and operation pages answer what an operator should inspect next, using domain-specific counters and scoped evidence.
- Copy distinguishes durable state from ephemeral/live state and avoids implying replay, recovery, crash-safe ownership, exactly-once delivery, or durable downstream execution where Fitz does not provide it.

## Domain Findings And Fixes

- KV: The overview and resource browser already center current authoritative state. Smoke coverage asserts committed rows, transaction pressure, authoritative wording, and broker-local transaction sessions.
- Queue: The overview used implementation wording around warm actors. It now frames Queue as durable work backlog with ready, delayed, inflight, and dead-letter pressure. Resource detail now describes current backlog, live reservations, dead-letter decisions, and broker-observed transitions without presenting the timeline as durable history.
- Stream: The overview already emphasizes durable history and replay lag. The workflow questions now focus on reader lag instead of implying broker-owned consumer history.
- Lease: The overview and resource pages now make ephemeral ownership, TTL, waiters, and non-crash-safe continuity explicit. The ownership console history mode describes bounded broker-local evidence rather than durable ownership continuity.
- Notice: The overview already calls out live ephemeral fanout and disconnect/restart loss. Workflow language now focuses on live fanout drops rather than generic failure tracing.
- RPC: Overview and resource copy now consistently says pending requests, live workers, and in-memory evidence, avoiding durable queue language.
- Schedule: Overview and resource pages already distinguish durable timing intent from downstream delivery. Pending fire claims now describe persisted timing claims awaiting live handoff.

## Remaining Follow-Up Risks

- Some visual screenshots are generated by Playwright only during e2e runs; keep the domain overview template suite current when new domain routes are added.
- Queue and Lease comparison/history panels depend on broker-observed evidence. If backend APIs add durable history later, the UI copy should be revisited in the same change.
- Schedule can show broker-observed execution counters; it must continue to label them non-authoritative and not downstream execution history.
